# E4 twin-error sweep: measured findings

Source: `E4_REPORT.md`, `sweep.csv`, `d_vs_e_discordance.csv`, `summary.json` in this folder (generated by
`python -m phase3_final.twin_error_sweep sweep` from the caches built with `... cache`). Rates are conditional:
**UA** = unsafe accepts / unsafe proposals, **FR** = false rejects / safe proposals. Dev = B4/UsCarrier/Cogentco
val (136 cases); holdout = GEANT (1600) + Kdl (8). For σ > 0 there are 3 noise replicates per case.

## Findings

1. **Without twin error, uncertainty never matters.** At σ = 0 the improved twin's mean already reproduces the
   oracle. D, E1, E2 and F make identical decisions on all 136 dev and 1608 holdout cases.
2. **Under twin error, the mean-only gate leaks unsafe decisions and the uncertainty-aware gate does not.**
   D's unsafe-accept rate grows with σ (holdout 0.17% → 1.24% of unsafe proposals). In paired comparisons
   every holdout discordance goes one way: D accepts an unsafe proposal that E1 rejects 6 / 23 / 34 / 50 times at
   σ = 0.05 / 0.1 / 0.2 / 0.4, and the reverse happens 0 times.
3. **The price is false rejections.** E1 rejects 11–76% of safe proposals as σ grows (E2: 20–95%), against
   4–24% for D. Because rejected cases fall back to shortest/equal, applied satisfaction is unchanged on holdout
   (0.9760 for all gates) and differs by less than 0.001 on dev.
4. **Against an equally conservative mean-only gate, the uncertainty term adds no measurable safety.** The
   control Dm (mean-only, with a margin tuned on dev to match E1's false-reject rate) reaches the same holdout
   unsafe-accept level as E1. Paired discordance is Dm-only vs E1-only unsafe accepts: 1 vs 0 (σ = 0.1), 0 vs 2
   (σ = 0.2), 0 vs 0 (σ = 0.4). False-reject rates are similar, with neither consistently lower. In this error
   model, E's advantage over D comes from being more conservative, not from per-link uncertainty information.
   This is a **negative result for the specific claim that calibrated uncertainty beats mean-only gating**; it
   does not show that uncertainty is useless.
   - Likely reason: member-wise noise is i.i.d. and proportional to load, so the ensemble spread is roughly
     proportional to the mean, and μ + kσ behaves like a uniformly tighter mean limit. An uncertainty-aware gate
     should only outperform a constant margin when twin error is heteroscedastic, i.e. concentrated on some
     links or regimes. Neither error model here produces that.
5. **Degraded twins stay near the physics model.** Twins trained on 10/25/50% of the data for 1/2/4 epochs reach
   validation utilisation MAE of 6.8e-5, 3.0e-3 and 5.0e-4 (reference 4.9e-5). None produces an unsafe accept
   under any gate, and E only adds 0–2 false rejects. Physics anchoring (every multiplier starts at 1) makes the
   twin robust to reduced training. Twin error therefore has to be injected (error model 1) to stress the gate.
6. **Coverage.** With the frozen validation scale c = 0.955, 2-std conformal coverage stays at 0.98 under every
   σ, because member spread grows with the injected error. Refitting c per σ on dev validation (E1r) gives
   c = 0.75 and slightly fewer false rejects than E1, at a slightly higher unsafe-accept rate (≤ 0.12%).
7. **Proposals are mostly far from the boundary.** Only 7% (GEANT) to 25% (B4) of proposals have a true MLU in
   [0.9, 1.1]. Gate errors can only happen near the boundary, which bounds how much any gate refinement can
   matter on this policy.

Formal paired tests (McNemar / Wilcoxon with Holm correction) are in the statistical analysis (`results/phase3_final/stats/`).
